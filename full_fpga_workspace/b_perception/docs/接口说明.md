# FPGA 到 RK3588 数据接口 V3

## 链路划分

图像和传感器数据使用两条独立物理链路：

```text
OV5640 -> FPGA -> DDR3 -> HDMI1 -> 双头 HDMI 线 -> RK3588 HDMI RX
TFmini-S / WT901 -> FPGA -> GPIO0_13 -> CP2102 RXD -> USB -> RK3588
```

HDMI 不承载传感器二进制帧，USB-TTL 不承载图像。摄像头异常不会停止
遥测定时发送，传感器未就绪时仍发送带状态位的心跳帧。

## 物理接口

| 用途 | FPGA 信号 | FPGA 球位 | 板级连接 |
|---|---|---|---|
| TFmini-S 输入 | `tof_uart_rx` | A13 | GPIO0_0，接 TFmini-S TX |
| WT901 输入 | `imu_uart_rx` | A14 | GPIO0_1，接 WT901 TX |
| RK3588 遥测输出 | `sensor_uart_tx` | D15 | GPIO0_13，接 CP2102 RXD |
| 串口参考地 | GND | 板载 GND | 接 CP2102 GND |
| 图像输出 | HDMI1 | K4/J4/L3/K3/L5/L4/M3/M2 | 接 RK3588 HDMI RX |

CP2102 只连接 RXD 和 GND，不连接 VCC、5V、3V3 或 TXD。UART 电平为
3.3 V TTL。官方管脚表给出了 GPIO 名称与 FPGA 球位，但没有给出 P7 的
物理针号映射，因此不使用未经确认的 P7 针号。

## 串口配置

- 115200 baud
- 8 data bits
- no parity
- 1 stop bit
- no flow control
- 20 frames per second

## V3 帧格式

每帧固定 28 字节，多字节整数均为小端序。

| 偏移 | 长度 | 字段 | 类型与单位 |
|---:|---:|---|---|
| 0 | 2 | 帧头 | 固定 `A5 5A` |
| 2 | 1 | 版本 | 固定 `01` |
| 3 | 1 | 消息类型 | `10` 表示传感器快照 |
| 4 | 1 | 负载长度 | 固定 21 |
| 5 | 2 | 序号 | uint16，每帧加 1 |
| 7 | 1 | 状态 | 位定义见下表 |
| 8 | 2 | 距离 | uint16，mm |
| 10 | 2 | 测距强度 | uint16 |
| 12 | 2 | 横滚角 | int16，0.01 degree |
| 14 | 2 | 俯仰角 | int16，0.01 degree |
| 16 | 2 | 航向角 | int16，0.01 degree |
| 18 | 2 | 测距错误计数 | uint16，饱和累计 |
| 20 | 2 | IMU 错误计数 | uint16，饱和累计 |
| 22 | 4 | FPGA 运行时间 | uint32，ms |
| 26 | 2 | CRC16 | 低字节在前 |

CRC 使用 CRC-16/CCITT-FALSE，多项式 `0x1021`，初值 `0xFFFF`，不反射，
无最终异或。计算范围是偏移 2 到 25，不包括两字节帧头和 CRC 本身。

状态字节：bit0 表示曾收到 TFmini-S，bit1 表示曾收到 WT901，bit2 和
bit3 表示相应数据在最近 500 ms 内更新，bit4 和 bit5 表示相应错误计数
非零，bit6 和 bit7 保留为 0。

## RK3588 接收

```bash
python3 sensor_link_receiver_v3.py /dev/ttyUSB0
```

接收器会搜索帧头、检查长度和 CRC，并在错误后自动重新同步。正常输出示例：

```text
seq=   42 distance=  816 mm roll=  -1.23 pitch=   4.56 yaw=  -7.89 fresh=1/1 errors=0/0
```
